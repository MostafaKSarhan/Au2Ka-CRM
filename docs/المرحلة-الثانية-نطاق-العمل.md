## 1. تعارض يجب حسمه قبل البرمجة

ورقة الطلبات (25/10) بتطلب حاجات **مش موجودة** في الـ 11 وحدة المسعّرة، وبعضها
مستثنى صراحةً في بند "خارج نطاق العرض":

| الطلب في ورقة 25/10 | وضعه في عرض السعر Q-2026-02 |
|---|---|
| الفروع (إضافة/تعديل/حذف، مرتبطة بالمدينة والدولة) | ❌ "تعدد الفروع" مذكور تحت **غير مشمول** |
| الموظفون/الفنيون مرتبطون بالفرع | ❌ تابع لتعدد الفروع — غير مشمول |
| موديلات السيارات (كتالوج) | ⚠️ غير مذكور صراحةً — ضمني في M3 |
| قطع الغيار (إضافة/تعديل/حذف) | ✅ مشمول في **M10** (مستودع واحد فقط) |
| العملاء (إضافة/تعديل/حذف) | ✅ موجود أصلاً في v1.0 |
| الباك أب للنظام والحفظ عندهم | ⚠️ مذكور كتكلفة تشغيلية (5$ شهريًا) لا كوحدة برمجية |

لازم يتحسم مع العميل كتابةً: يا إما يتضاف لنطاق العرض بسعر إضافي، يا إما يتشال.

> **القرار المتخذ هنا:** تنفيذ الفروع والموظفين **كبنية تحتية** (جدول Branch + ربط
> المستخدم والعميل والكرت بالفرع) لأن باقي الوحدات هتحتاجها، مع إبقاء التشغيل بفرع
> واحد افتراضي حتى يعتمد العميل التوسعة.

## 3. ترتيب التنفيذ المعتمد

### R0 — الأساس (الحالي)
البنية التحتية اللي كل الوحدات بتقف عليها، وهي نفسها البنود الصريحة في ورقة 25/10:

- [x] **الدول والمدن** — السعودية + مدنها كبيانات مرجعية
- [x] **الفروع** — CRUD مرتبط بالمدينة/الدولة
- [x] **الموظفون** — توسعة `User` بربط الفرع + CRUD من لوحة التحكم
- [x] **موديلات السيارات** — كتالوج ماركة/موديل بدل القائمة الثابتة في الكود
- [x] **قطع الغيار** — كتالوج أصناف بأكواد وأسعار (أساس M10)
- [x] **العملاء** — موجود، يتراجع ويتربط بالفرع
- [x] **الباك أب** — تصدير قاعدة البيانات وتنزيلها من لوحة التحكم

### R1 (أسبوع 2–4): M1 الاشتراكات · M3 ملف السيارة · M6 الرسائل

- [x] **M1 الاشتراكات والباقات** — باقات، اشتراكات، تجديد، خصم تلقائي، تقرير المشتركين
- [x] **M3 الملف الكامل للسيارة** — خط زمني، سجل عداد، قطع بضمان، مستندات بتنبيه، أرشيف صور، رابط مشاركة + QR
- [x] **M6 الرسائل والتنبيهات** — قوالب عربي/إنجليزي، طابور بإعادة محاولة، سجل كامل، تنبيهات داخلية، إيقاف استقبال

### R2 (أسبوع 4–6): M2 التقرير الشهري · M4 المواعيد

- [x] **M2 التقرير الفني الشهري** — قائمة بنود، نموذج فحص، مؤشر صحة، توليد شهري، تقرير قابل للطباعة
- [x] **M4 حجز المواعيد وأولوية المشتركين** — تقويم، طاقة يومية، فتحات محجوزة للمشتركين، تذكير 24 ساعة، تحويل لكرت

### R3 (أسبوع 6–8): M5 الإحالات · M7 بوابة العميل · M10 المخزون · M11 PWA

- [x] **M5 الإحالات والعملاء المميزون** — أكواد وروابط و QR، نقاط برصيد وسجل، مستويات عملاء، تقرير الإحالات
- [x] **M7 بوابة العميل** — دخول برمز تحقق، ملف السيارة، حالة الكروت، حجز ذاتي، الاشتراك وكود الإحالة
- [x] **M10 إدارة المخزون وقطع الغيار** — إدخال وصرف وجرد، سجل حركة برصيد، تنبيه إعادة الطلب، تقرير الراكد والأكثر استهلاكًا
- [x] **M11 تطبيق الجوال PWA** — قابل للتثبيت، يعمل دون اتصال، أيقونة ولافتة تثبيت ومؤشر انقطاع

### R4 (أسبوع 8–10): M8 واتساب الرسمي · M9 ZATCA · اختبار ونشر وتدريب

## 5. قواعد فنية ثابتة لكل الوحدات

- **كل شاشة جديدة لازم يكون لها ترجمة عربي/إنجليزي** في `LanguageContext.tsx`.
- **الحذف دايمًا soft delete** (`deletedAt`) زي باقي النظام.
- **صلاحيات:** إدارة البيانات المرجعية (فروع، موديلات، قطع، موظفين) = ADMIN فقط.
- **الحفاظ على كل البيانات القائمة** — أي تعديل على قاعدة البيانات لازم يكون متوافق
  مع الموجود (المشروع مفيهوش `prisma/migrations`، التشغيل المحلي بـ `prisma db push`).
- **لا كسر لعمل v1.0** — ده شرط صريح في أول سطر من ورقة الطلبات.
