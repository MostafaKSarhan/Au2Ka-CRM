# قائمة التسليم

ما تمّ، وما يُفعل يوم التسليم بالترتيب، وما ينتظر الورشة. مكتوبة لأن
نصفها خطوات تُنسى بصمت: لا تُصدر خطأً، بل تترك النظام يعمل بنصف طاقته
ولا يبحث أحد عن السبب.

آخر تحديث: ٢٤ نوفمبر ٢٠٢٦.

## تمّ

- المرحلة الثانية كاملة، منشورة على `https://au2ka.faslacloud.com`
- ربط واتساب الرسمي: التطبيق منشور، الـ webhook متصل، ثمانية قوالب عربية
  معتمدة ومربوطة، ورسالة حقيقية خرجت ووصلت. التفصيل في
  [ربط-واتساب-الرسمي.md](ربط-واتساب-الرسمي.md)
- بيانات العرض مُسحت: لا عملاء ولا كروت ولا فواتير ولا طلبات انضمام،
  والمخزون صفر. والبيانات المرجعية باقية — ٢٠ بند فحص، ٦٦ موديل سيارة،
  ٢١ مدينة، ٣ باقات، ١٠ أصناف قطع، أيام العمل، والفرع الرئيسي
- الرقم الضريبي الحقيقي محفوظ

## يوم التسليم — بالترتيب

### ١) كلمة مرور المدير

كلمة المرور الأولى ما زالت في `/root/au2ka-first-login.txt` على الخادم
منذ ٢١ نوفمبر. تُغيَّر من داخل النظام أولًا، ثم:

```
ssh root@152.239.119.212 'shred -u /root/au2ka-first-login.txt'
```

الترتيب مقصود: حذف الملف قبل تغيير كلمة المرور يضيّع الدخول.

### ٢) حساب العرض

| الجوال | الاسم | الدور |
| --- | --- | --- |
| `0500000001` | مدير النظام | ADMIN |
| `0555000000` | **حساب العرض** | **ADMIN** |

الثاني أُنشئ للعرض، ورقمه يُخمَّن من أول نظرة، ودوره مدير كامل. يُحذف يوم
التسليم — ولم يُحذف قبله لأن الورشة تستعمله الآن في التجربة.

### ٣) حسابات الموظفين

لا يوجد سوى حسابَي مدير. الاستقبال والفنيون يحتاجون حسابات باسم كل واحد
ودوره، فسجلّ من فعل ماذا لا معنى له إن دخل الجميع بحساب واحد.

### ٤) رفع إيقاف الرسائل

بعد مسح بيانات العرض لم يبقَ عميل موقوف، والعملاء الجدد يُنشأون
بالافتراضي `messagingOptOut = false`. فإن أُدخلت بيانات عملاء قدامى
بالاستيراد، يُتحقق أن الحقل صفر عليهم جميعًا:

```sql
SELECT COUNT(*) FROM Customer WHERE messagingOptOut = 1 AND deletedAt IS NULL;
```

### ٥) الفحص الشامل ثم التنظيف

```
cd backend
API_URL=https://au2ka.faslacloud.com WEB_URL=https://au2ka.faslacloud.com npm run check:system
npm run check:reset
```

الأول يكتب بيانات اختبار ويمرّ على النظام كله، والثاني يمسحها. وإعدادات
الربط (واتساب والزكاة) لا يمسّها التنظيف — يطبع حالتها في آخره للتأكد.

### ٦) النقل إلى خادم الورشة

بعد سداد كامل قيمة المشروع وتأكيد الاستلام. الخطوات في
[الاستضافة-والتسليم.md](الاستضافة-والتسليم.md).

## على الورشة

### الربط بهيئة الزكاة — الوحيد المعلّق فعلًا

البيئة `SANDBOX` والربط غير مفعّل. المطلوب منهم:

1. رقم السجل التجاري
2. اسم المنشأة بالعربي كما في الشهادة الضريبية
3. العنوان الوطني: رقم المبنى + الشارع + الحي + المدينة + الرمز البريدي
4. كود من بوابة «فاتورة» — ينتهي خلال ساعة، فيلزم أن نكون معهم على الخط

> العنوان المحفوظ الآن (الرياض / العليا) قيمة نموذجية، وموقع الشركة
> الرسمي يذكر العزيزية بالمدينة المنورة. الشهادة هي الفيصل، والعنوان في
> الفاتورة يجب أن يطابق المسجّل وإلا رُفضت.

ولا يصح تسليم النظام «شغّالًا رسميًا» قبلها: ورشةٌ مسجّلة في ضريبة القيمة
المضافة فواتيرها يجب أن تكون إلكترونية معتمدة، وهذا بند قانوني لا تحسين.

### وسيلة دفع عند Meta

الرسائل التي يبدأها النظام — جاهزية السيارة، تذكير الموعد، قرب انتهاء
الوثيقة — تُحاسب عليها Meta بالمحادثة. للحساب الجديد سقف مجاني، وحين
ينفد تتوقف كلها. بند تشغيلي شهري يُقال قبل التسليم لا بعده.
